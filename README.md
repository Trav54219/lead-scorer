# Lead scorer

Cleans and scores a lead list against an ICP before it goes into a sequencer. Data-quality gates run
first, because sending to a bad address costs more than not sending: a gate rejects a lead with a
reason, and only leads that pass get a 0 to 100 fit score.

```
python make_sample.py                       # regenerate the synthetic sample
python -m lead_scorer --input sample_data/leads.csv --icp icp.json
```

```
input leads:      325
rejected:         85  {'free_mail': 21, 'invalid_email': 13, 'role_inbox': 27, 'duplicate_email': 24}
passed the gate:  240
send-ready (>=60): 121
```

`out/clean.csv` is sorted by score with the reasons for each; `out/rejected.csv` lists every rejected
lead with its reason, so nothing disappears silently.

## Gates (reject)

invalid email syntax, free-mail domains (gmail, yahoo and so on), role inboxes (`info@`, `sales@`;
switch on with `"allow_role_inboxes": true`), duplicate email, and duplicate person (same name at the
same company domain, different address).

## Score (0 to 100)

40 for title matching an ICP persona, 25 for headcount in your band, 25 for keywords in the company
description (full marks at two hits), 10 for the email living on the company's own domain.
Everything is configured in `icp.json`; the weights are in `lead_scorer/score.py`.

## Limits

- It does not check that a mailbox exists. Run a verifier (MX and SMTP checks) before sending.
- Keyword fit is a substring match on a description you supply; it is a filter, not understanding.
- The sample is generated by `make_sample.py` with fictional people and `.example` domains. The
  rejection counts above describe that synthetic data, not real-world rates.
